Objectives:

  • The objective of this lab is to give students practice with Linux file and directory permissions. Students will set ownership and permissions for shared team folders, test access as different users, and explain permissions in both octal and rwx form. Getting permissions right is a core part of keeping a server secure.

Background

The Marketing and Development teams each need a shared folder. Each team should be able to work in its own folder, Development needs to read Marketing's files but not change them, and nobody else should get in. You will be working on the two servers you set up in the Server Setup lab: your Red Hat based server and your second server.

Requirements

  1. Create a group for each team using users from the User Management lab, and create the two shared directories.
  2. Set ownership and permissions so each team can read and write its own folder, Development can only read Marketing's folder, and everyone else is blocked.
  3. Make sure new files created in a shared folder automatically belong to that team's group.
  4. Create a hidden file in each folder, and a symbolic link from each user's home directory to their team's folder.
  5. Find any world-writable files on the system, and decide whether each one should stay that way.

Acceptance Criteria

  • If you had to look anything up to figure out a command, cite your source with a link to the reference.
  • Access is tested by logging in as a user from each team and as an outsider, with screenshots showing a successful write, a read-only attempt, and a denied attempt.
  • Your permissions are explained in both octal and rwx form.
  • Every change is recorded in your change log from the Installs, Updates, and Documentation lab, with the date. For permission changes, record the permissions before and after. A sample change log showing the format is linked under Resources.
  • Every terminal screenshot shows your prompt with your username and hostname, and either the output of date or a note beside the terminal with your name and the term. Hostnames must match your server inventory from the Server Setup lab.

Deliverables

Audience: another administrator who will maintain these folders after you. Assume technical knowledge but not expertise. Screenshots are helpful to go with your descriptions.

Make sure your deliverables include documents for BOTH servers, clearly labeled with what the document is and which server it's for.

  • A permissions plan: who can do what in each folder, and why.
  • The commands you used, with your test screenshots.
  • Your list of world-writable files, and your decision on each one.
  • Your updated change log.
