Request

Request: DATA-3172
Requested by: Operations manager at your company
Data: Your data set from the Introduction to Data lab

Background

Before anyone relies on this data, your manager wants to see that it can answer real business questions, and that your queries are documented so the rest of the team can reuse them. You'll start with a quick SQL refresher as training, then load your data into a database and put it to work.

Learning Outcomes

By the end of this lab, you will be able to:

  • Write basic SQL queries to select, filter, and sort data
  • Explain what each part of a SQL query does
  • Turn business questions about your data set into documented SQL queries, with a business justification for each
  • Evaluate a SQL tutorial, including where you needed help

Lab Instructions

Screenshots

Several parts of this lab ask for a screenshot. Each screenshot should have your name, term, and year. One of the easiest ways to do that is make a text document with your name and term/year on your computer and save it to use all term. Any screenshots that don't include this information won't be counted.

Part 1: SQL Review Tutorial

Go through these 5 sections of SQLBolt (linked under Resources), and complete the exercises at the end of each one:

  • SQL Lesson 1: SELECT queries 101
  • SQL Lesson 2: Queries with constraints (Pt. 1)
  • SQL Lesson 3: Queries with constraints (Pt. 2)
  • SQL Lesson 4: Filtering and sorting Query results
  • SQL Review: Simple SELECT Queries

Take a screenshot of each section after you complete its exercises. Make sure you have the green checkmark on each problem. Then answer these questions:

  1. Which, if any, questions did you find challenging? Why?
  2. How many of the questions did you need a hint on? Why?
  3. What is your review of this tutorial? What would you change or fix?
  4. Pick one query you wrote and explain what each part does: SELECT, FROM, WHERE, and ORDER BY.

Part 2: Business Questions About Your Data

Now use SQL on your own data set from the Introduction to Data lab. Books are my example data only, so your questions and queries must be about your own data.

  1. Load your data set into a database as a single table. You will organize your data into multiple tables later in the term, so one table is fine for now. Here's the way I suggest, which runs in your browser with nothing to install. The tools are linked under Resources.
    1. Open my CSV to Database Converter, and choose your CSV file. Keep the first 100 to 1,000 rows, since bigger databases can cause errors in browser tools. Select Convert, check the summary, and download your database.
    2. Open SandboxSQL, use Load a Database, and choose the file you downloaded.
    3. Check that it worked by running SELECT COUNT(*) on your table. The count should match the number of rows the converter showed.
    You can use a different tool if you prefer, as long as you turn in a database file, not a CSV file or a spreadsheet.
  2. Write 5 business questions that someone at the company from your data card might ask about your data.
  3. Write a query that answers each question. Across your 5 queries, use WHERE, ORDER BY, and at least one WHERE with more than one condition.
  4. Document each query using the format in the sample query documentation (linked under Resources). Each one needs a header comment with the business question, who is asking, a business justification, and any notes, followed by the query and a short summary of the result. Your result summary must quote specific numbers or values from your results, such as how many rows came back or the top value.
  5. Take a screenshot of each query and its results.
  6. Export your database to turn in. In SandboxSQL, use the Export button, which saves it as a .sqlite file. SandboxSQL doesn't always keep your work if you close the page, so export at the end of each session, and use Load a Database to open your .sqlite file next time.

Acceptance Criteria

This request is done when:

  • All 5 SQLBolt sections are complete, with a green checkmark on every problem
  • Your data is loaded into a database as one table, and your database file is turned in
  • 5 business questions that someone at your company would actually ask
  • Each question has a query that runs and returns results that answer it
  • Each result summary quotes specific numbers or values from your results
  • Every query is documented in the sample format, with a business justification
  • Across your queries, you use WHERE, ORDER BY, and at least one WHERE with more than one condition
  • Every screenshot follows the screenshot rules

Deliverables

Two files:

  1. A document that includes Part 1, your 5 SQLBolt screenshots and your answers to the 4 questions, and Part 2, your 5 documented queries with a screenshot of each one and its results
  2. Your database file

Audience: your manager and the rest of the data team.
