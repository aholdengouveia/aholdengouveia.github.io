About this tool

The Database Explorer turns your CSV file into a real database, so you can see how a database is different from a spreadsheet. You choose the rules for each column, work with one record at a time, link tables together, and see the SQL behind everything you do.

Everything happens in your browser. Your file isn't uploaded anywhere, and you don't need to install anything or make an account. Nothing is saved for you. Use Save database to download your work, and open that file again next time.

You have unsaved changes. Save your database before you close this page.

Make a new database from your CSV file

Your CSV needs 100 to 1,000 rows of data and at least 7 columns, with column names in the first row.

Don't have a CSV? In Google Sheets, select File, then Download, then Comma Separated Values (.csv). In Excel, select File, then Save As, and choose CSV.

Practice files: try the tool with my book data first

Use these to see how the tool works, and what its error messages look like. For your labs, use your own data. Download a file, then choose it above.

  • books-sample.csv: 150 books with 12 columns, and nothing wrong with it. This one becomes a database without any problems.
  • books-sample-bad-values.csv: the same books, with values that break the rules, such as N/A for pages, 1,024 with a comma, and $5.09 for a price. The tool will guess Text for those columns. Change them to Whole number or Decimal to see the problems.
  • books-sample-bad-rows.csv: a title with a comma that isn't in quotes, a duplicate book_id, and empty values. Choose book_id as your primary key, and make title required, to see all the problems.
  • books-sample-too-small.csv: only 60 rows and 6 columns, to see what happens when a file doesn't meet the requirements.

The book data comes from the Best Books Ever Dataset by Lorena Casanova Lozano and Sergio Costa Planells, shared under a CC BY-NC 4.0 license. I picked 150 books and 12 columns, and added the mistakes on purpose.

Set up your table

A database sets rules for each column before any data goes in. Check each column's name, type, and whether it's required, then choose a primary key. I've made a guess for each one based on your data.

Letters, numbers, and underscores only, starting with a letter.

The primary key identifies each record. Every value must be unique, and none can be empty. If none of your columns work, choose an automatic ID number.

Your columns

Each card is one column from your CSV. The highlighted card is your primary key.

Text is anything. Whole number is numbers like 4 or 1200. Decimal is numbers like 4.5. Values that start with 0, like ZIP codes, should be Text so the 0 isn't lost.

Relationships

Related tables are linked with keys. A foreign key is a column in one table that points to the primary key of another table.

Your diagram

Move a table: drag it, or select it with Tab and use the arrow keys. Link two tables: select a column (it turns yellow), then select the primary key it should point to (possible keys turn green). Press Escape to cancel. You can also link tables with the form below the diagram.

Optional: see your tables in ChartDB, a professional diagram tool

ChartDB is a free tool database professionals use to draw diagrams. Select the button below to copy the SQL that describes your tables. Then in ChartDB:

  1. Start a new diagram.
  2. When it asks What is your Database?, choose SQLite, then Continue. Don't choose Generic. A Generic diagram can't import SQL, and you'll get an error that says "Unsupported database type: generic".
  3. On Import your Database, select SQL Script, not Smart Query. You can skip ChartDB's instructions about sqlite3, because this button already did that step for you.
  4. Paste what you copied, and select Import.
